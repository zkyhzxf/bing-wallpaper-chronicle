# 必应壁纸 · 全量下载器

独立的小工具，把 2009 年至今的必应每日壁纸**一次性下到本地**，文件命名与主程序完全一致，下完可以直接拿去「接管目录」。

## 为什么单独做一个

主脚本也能批量下（`-ExportRange`），但它有两个限制：

- 每一次下载都要起一个 PowerShell 进程，几千张会很慢
- 画质是固定的，不能按需选

这个工具用 C# 直接下载，**4 线程并发**，并且能选画质。

## 用法

双击 `BingWallDownloader.exe`：

| 项 | 说明 |
|---|---|
| **日期范围** | 默认 2009-07-13 ~ 今天 |
| **画质** | 见下表 |
| **保存到** | 图片目录，默认 `D:\BingWall-全量` |
| **索引目录** | 自动找主程序的 `archive` 目录；找不到时手动选 |

点「开始下载」，进度条和日志会实时更新。中途可以「停止」，**已下载的不受影响，下次接着下**。

### 画质三档

| 档位 | 实际行为 | 典型体积 |
|---|---|---|
| **最高可用**（默认） | UHD 3840×2160 → 1080p → 镜像原图，逐级降级 | 2019 年后约 5 MB/张，早期约 200 KB |
| **1080p** | 1920×1080 → 镜像 | 约 340 KB/张 |
| **只用镜像** | 直接走第三方镜像（1366×768） | 约 200 KB/张 |

全量 6339 天的体积估算：

| 档位 | 体积 |
|---|---|
| 最高可用 | ≈ 15 GB |
| 1080p | ≈ 2 GB |
| 只用镜像 | ≈ 1.3 GB |

> **分享给别人建议选 1080p** —— 15 GB 打包不现实。

## 文件命名

```
{YYYYMMDD}_{slug}.jpg

20090713_GreenTurtle.jpg
20190601_OHR.HighTrestleTrail.jpg
```

这个格式与主程序的归档目录完全一致。主程序找图靠的是：

```csharp
Directory.GetFiles(dir, date + "_*.jpg");
```

**只要开头是 8 位日期就能认出来**，后半段随便。

标题不靠文件名 —— 靠主程序里的索引按日期查，所以接管后标题、版权、往年的今天全部正常。

## 断点续跑

目录里已有 `{日期}_*.jpg` 就跳过。中断了直接再点「开始下载」即可，**不会重下**。

## 失败清单

下不来的日期会写进保存目录的 `_download-fail.txt`：

```
20180901	远程服务器返回错误: (404) 未找到。
```

这些多半是源站本来就没有那张图。可以换个画质档再跑一次，或者单独用主程序 `-Date 20180901` 试。

## 下完之后：接管测试

1. 托盘菜单 → **接管目录…**
2. 选刚才下载的目录
3. 程序会写入 `config.json`，然后只读挂载这个目录
4. 菜单第二项会显示「**收藏家模式 · 目录名**」

**退出时选「留在接管模式」或「备份并退出」，不要选直接退出** —— 那个会把沙盒整个送进回收站。

## 自检模式

命令行（无界面，结果写进 `%TEMP%\bwd-test.log`）：

```
BingWallDownloader.exe --test 20090713 20090715 D:\test-dir D:\tools\bing-wallpaper\archive
```

用来验证索引能读、源能用，不用点界面。

## 编译

```powershell
pwsh -File tools\Downloader\build.ps1
```

产物在 `dist\BingWallDownloader.exe`（约 22 KB，无外部依赖，只需要 .NET Framework 4.x）。

## 已知限制

- **必须先安装主程序并运行过一次**，让它把索引释放到 `archive\` 目录 —— 这个工具只负责下图，不含索引
- 依赖第三方镜像（anerg / wilii），站点改版或失效时会走失败清单
- 2009–2016 的老图只有 1366×768 或 1920×1080，没有 4K（当年必应就没出更高分辨率）
- 下载器不写索引、不改状态、不碰壁纸，纯下载

## 重试与失败处理（v1.1）

| 项 | v1.0 | v1.1 |
|---|---|---|
| 单个地址重试 | 无（只换候选） | 3 次，退避 1s/2s/3s |
| 404 / 410 | 换候选 | **直接换候选**（明确没有，重试无意义） |
| 429 / 403 | 换候选 | 全局冷却 2 秒后重试 |
| 超时 / 连接重置 / 5xx | 换候选 | 退避后重试 |
| 并发 | 固定 4 | 可选 2 / 4 / 6（默认 4） |
| `.part` 残留 | 异常时留下 | `finally` 里清；启动时清 10 分钟以上的旧残留 |
| 失败清单 | 只在本轮结束时写 | **实时追加** `_download-fail.txt` |
| 画质校验 | 无 | Best 档 + 2019 起读真实宽度，`< 3000` 记入 `_lowres.txt` |

### 补失败项的方法

失败的天没有落 `.jpg`，所以**再点一次「开始下载」就会自动只补这些天**——已有文件跳过，失败的重试（这次每个地址 3 次 + 退避）。不需要清空目录。

### 三个输出文件

| 文件 | 内容 |
|---|---|
| `_download-fail.txt` | `日期 \t 原因`，实时追加 |
| `_lowres.txt` | 该是 UHD 却只有 1080p/更小的日期 |
| `*.part` | 只在下载中短暂存在；中断超过 10 分钟会被下次启动清掉 |
